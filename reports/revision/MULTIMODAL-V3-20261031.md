# 多模态证据修复和第二版保留验证

## 边界

原五篇论文和第一版 ELMo、Sentence-BERT 保留集的原始结果、索引及两本旧账本均保留；第一版已用于本轮诊断，**降为开发集**，其历史结论见 [第一版报告](MULTIMODAL-HOLDOUT-20261031.md)。开发复验不能计入新保留成绩。新集使用 BERT、Transformer-XL 两篇不同论文，11 问和 3 条图搜图；题集、原 PDF、题目和金标的来源及哈希见 [题集说明](../../data/eval/multimodal-holdout-v2/README.md)。[另一 agent 的执行前原页核查](MULTIMODAL-HOLDOUT-V2-PRE-AUDIT-20261031.md)不是人工或盲审。[冻结清单](MULTIMODAL-HOLDOUT-V2-FREEZE-20261031.json)在新集首次解析前写入。

## 实现

- 图像对象不再隐含发送图注和表格序列化文本；唯一、同论文、同 PDF、同页且文本精确一致的图注由单独的文本证据 ID、页码和 bbox 引用。相邻正文只能按同列、同页和几何关系作为独立候选补入，是否支持声明仍需核对。
- 逐声明检查其引用文本中的显式数字和常见单位；数字匹配本身不证明语义。引用图表时数字状态为 `unknown_visual`，仍需看图核对。若引用缺少数字条件，可在成功保存本地原声明时发起一次显式 `repair_citations` 请求，仅允许增加已选、同论文、位置有效的文本引用；修复后重新校验引用、数字和逐声明自检。无法确认时拒答。
- 原生成声明、引用位置、逐项 verdict、被删声明、修复结果和最终拒答原因保存在本地审计，模型请求逐次记录；不向 Langfuse 发送论文正文、图片、私人会话或凭据。同模型自检只是辅助，有误拒及漏判风险。
- 论文简称仅由唯一标题前缀或正文中显式定义的名称产生，名称碰撞不采用；历史指代、歧义与不确定范围仍保守处理。保留少量只在稠密路召回的不同候选供同一重排器检查，不改变最终 Top-5 或给该候选额外融合票数。
- ELMo 第 5 页表格和图注间唯一的近邻几何关联带 `geometry_unique_unverified`、来源图注 ID 和两个 bbox；未知或冲突继续标 unknown。它是可审计推断，不是通用正确性保证。真实 Docling 输出及每层候选诊断见 [Docling 开发诊断](MULTIMODAL-DOCLING-DIAGNOSTIC-V3-20261031.md)。

## 开发复验

八个旧题的真实运行在 `runs/multimodal-diagnostic-v3-20261031/`：h01 引用独立图注及图形区域；h02 给出图与正文支持的答案，但这次自检未重现原先的误判；h04 表格目标排第 2，关联状态为几何推断；h07 初次复验仍漏引用数值条件；h09 不再误澄清但因证据不足拒答；h10 恰当澄清、h11 恰当保留 unknown；h12 正确回答。

`runs/multimodal-diagnostic-v3-decomposed-20261031/` 的另一次开发复验启用分论文检索，h09 和 h12 均回答；h09 的指定 D19 摘要仍未进入最终 Top-5，回答使用受控扩展的正文。之后，`runs/multimodal-numeric-repair-dev-20261031/` 首次数值修复未补足引文，按规则拒答；`runs/multimodal-numeric-repair-dev-v2-20261031/` 的一次针对性复验将“10,000”所在摘要块增加到对应声明引用，重核后回答。两次原生成、修复请求和 verdict 均保留，不能将后一次当作首次结果。

[独立 agent 开发复验审核](MULTIMODAL-V3-DEVELOPMENT-AUDIT-20261031.md)指出：h07 修复后第二条仍用 “this” 指代前一声明，整段联合引用可支持，但单独看该声明的引用不自包含。原 `claim-audit` 中新增引用只有 ID；为便于追溯，另生成本地 `joined-claim-audit.json`，把原始、修复及最终引用 ID 与各自来源坐标连接。该后处理不是语义验证，原始账本保持不变。

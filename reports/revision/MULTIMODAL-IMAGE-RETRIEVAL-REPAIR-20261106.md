# 图文检索修复、开发复测和冻结论文验证

**结果：部分改进，仍有未通过项。** 英文文搜图可选地结合图注词项后，开发集命中从 0/2 到 1/2；直接图片搜图注在显式图注子集内命中 2/3，但搜索全部文本仍为 0/3。纯图片开发例不再夹带另一篇论文的候选；新论文纯图片问答因模型输出不符合 JSON schema 而失败。中文文搜图、通用直接图搜正文和稳定视觉回答尚不能认为通过。

## 原因与改动

原双论文开发集中，三张图片的正确图注在全部文本中的原始 CLIP 排名为 21、20、55；前列出现参考文献及无关正文，说明文本池竞争和跨模态相似度均影响目标召回。图像之间的匹配较强，但不能用图搜图结果冒充直接图搜文本。新增 `--kind caption` 只搜索独立 CLIP 文本索引中的原图注，保留原文本 ID、页码和坐标；它改变候选子集，成绩需与全部文本分开。

英文 ULMFiT 查询的正确图在图注词项分支排第 1，但原先独立文搜图只使用 CLIP 图片向量。新增可选 `--caption-fusion` 对同一个 `(paper_id, chunk_id)` 图片实体的两个排名做 RRF，保留各分支排名；不把正文和图片视为同一实体。中文 BART 查询的图注中缺少中文对应词，其正确图仍未进入 Top-5。

先前纯图片问答将低排名图像及其图注一并送给模型，导致混入另一篇论文。现在只在每张用户图片的最高图像相似度至少 0.90、领先第二名至少 0.05，且可在图像数量上限内呈现时，选取这些候选及其独立可定位关联；否则不调用模型，返回 `image_match_uncertain`。Reflect 仍须比较用户图和论文图，分数不是匹配或语义证明。阈值基于少量开发案例制定，并非经校准的置信概率；对非近重复图片可能过度拒答，也不能排除高分误匹配。

可选 BGE 图注和表格分支现在逐路捕获查询失败，在允许降级时保留其他分支，并在 trace 中分别记录 `ok`、`empty` 或 `failed`；不匹配的索引在加载时仍报错。用户图片仍不具备论文引用身份。单元测试覆盖分支失败、证据隔离、缺少第二候选和阈值边界；这些替身测试不能替代真实评测。

## 一篇冻结新论文：独立于本轮开发的有限验证

在解析和建立新索引之前，冻结 [LoRA 原论文 v2](https://arxiv.org/abs/2106.09685) 的 Figure 1、两个中英文文本查询、一个图片查询、一个跨论文图片负例和一道混合问题。固定记录 `data/eval/multimodal-image-holdout-20261106/fixture.json` 的 SHA-256 为 `e5b4386ed2a00b6826f9845bd9b7fd890e14c51db07ef2f7a99b1cd31d13bae3`；原 PDF SHA-256 为 `e9a0d3128767db616085dc0f4e6e455e672e89af823e8ed1282793682787395a`。论文此前未进入本项目开发索引；本助手看过原页后制定题目，负例图片来自已见开发论文，因此**不是盲审或独立人工评审**，也不能作为整体准确率估计。原 PDF 和图片位于忽略目录，不随仓库提交。

Docling 实际解析 26 页，得到 262 个条目，其中 28 个图表、234 个文本；6 个空文本被跳过。目标 Figure 1 和独立图注均存在于实际索引，用户图片裁自同一原页后缩放，搜索时没有指定论文、图号或标准答案范围。真实输出 `output/image-holdout-frozen-20261106.json` 的哈希和精简指标另存在 `data/eval/multimodal-image-holdout-20261106/results.json`。

| 路径 | 冻结样本结果 |
|---|---|
| 文搜图 | 英文目标原 CLIP、融合均第 1；中文目标两者均未进入前五，1/2。 |
| 图搜图 | 目标图第 1，Hit@5 和目标 Recall@5 为 1/1；最高相似度约 0.986，第二名约 0.790。 |
| 直接图搜全部文本 | 指定图注未进前五，0/1。 |

| 跨论文负例 | 最高图像相似度约 0.750，门槛判为 uncertain；纯图片问答未调用模型并拒答。 |

目标问题需要图中“冻结预训练权重”和“训练 A、B”两项证据。混合问答的融合 Top-5 包含图和冻结权重正文，但图注经扩展才进入证据；图、图注、正文三项全部进入 Top-5 为否。回答的两项主要事实分别由 p2 正文和 p1 独立图注支持；**回答没有引用图像本身**，因此对于“图片显示什么”的引用完整性为部分通过。额外两条关于任务切换和初始化的声明与其 p2/p4 正文一致，但超出问题所需。助手对照原 PDF p1、p2、p4 核查，不是独立人工复核。

纯图片正例 Reflect 成功，但 Generate 返回了 schema 不允许的额外顶层字段，调用被严格校验拒绝，未产生最终回答；该真实失败保留在 `runs/clip-image-question-frozen-holdout-20261106/`。没有自动重试，也没有把原始模型文本当作完成答案。上述结果是该冻结论文的首次运行，未依据其输出更改实现或金标。

## 运行与剩余限制

本轮开发与冻结问答共 10 次真实 provider 请求：9 次通过结构校验、1 次 Generate 结构校验失败；provider 均返回 usage，输入 36,381、输出 2,729、总计 39,110 token，费用 unknown。每次上限 1024 输出 token、60 秒，不自动重试。负例被本地门槛拒绝，未产生模型请求。此前 83,548 token 的账本独立保留，不合并冒充本轮。

完整自动回归 **429 passed、1 skipped、73 warnings**；`git diff --check` 另行核查。Docling、CLIP 索引和模型分别使用本机既有独立环境与固定快照，未引入其他检索模型。测试、真实结果及本地输出哈希记录在上述结果 JSON。

原论文和裁图的重建使用 `scripts/prepare_frozen_image_holdout.py --help`，评测使用 `scripts/eval_frozen_image_holdout.py --help`；模型问答使用 `scripts/smoke_image_question.py --help` 并会发送图片及产生费用。两个输出路径都必须新建。模型与数据准备、示例命令及安全边界见 `docs/multimodal.md`。模型输出结构失败、缺少图片引用、中文检索未命中、全部文本直接检索漏图注和小样本阈值可靠性均仍待改进；任何未确认的图文关联、OCR 或数值都不能升级为已验证事实。
